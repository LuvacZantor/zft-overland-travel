# ZFT Overland Travel — Complication Content Library Draft

**Status:** Design draft only. Not implemented. Not committed to GitHub.

## Shared resolution model

- Each Complication result is a content prompt, not a forced solution.
- The GM may accept any plausible player approach and choose the relevant check, tool, spell, resource expenditure, save, roleplay resolution, or no roll.
- Outcome tiers remain **Strong Success / Success / Failure / Major Failure**.
- Support mitigation reduces an applicable consequence tier; it does not rewrite the original adjudicated outcome.
- Navigation delays modify **planned** travel time only. No Complication entry commits time to the ledger or world clock.
- Standard and Major use the same underlying table result. Major increases scope, persistence, stakes, or consequence rather than replacing the rolled result.
- Threat remains separate state. A Threat-bearing result may create/advance/reduce Threat according to the approved Complication Engine design; Immediate Threat triggers the Encounter Engine.

## Entry schema

Each primary complication has an outcome profile. Each d8 detail below provides a Standard frame, Major frame, suggested response palette, Support applicability, and Threat eligibility.

# Mechanical tags for later Journal-backed implementation

The content library should ultimately expose stable structured metadata alongside readable Journal text:

- `category`
- `primaryType`
- `detailId`
- `severity: standard | major`
- `consequenceTags` such as `delay`, `resource`, `condition`, `equipment`, `social`, `route`, `threat`
- `supportTags: supply | operational`
- `threatEligible`
- `suggestedApproaches`
- `outcomeGuidance`

The Journal/compendium content should remain the editable content source. The rules engine should consume stable IDs/tags and handle mechanical state, not hard-code the prose library.
